# 开发里程碑与验收

每项只包含一个可以独立审阅和验收的目标。完成实现、必要测试、示例和结果记录后
单独 commit；失败不标记完成，不以编译通过替代数值验收。
当前完成 M0–M3、M4a、M4d、M5、M6、M7 和 M8，M4 整体未完成；后续按研究需要独立立项。

2026-10-23：按讨论补充固定维度反演的全局/参考窗口交集边界、半空间约定与顶深对照，
独立验收见 [速度边界与半空间](velocity-bounds.md)。本项不引入自适应分层或模型选择。

## M0 架构与代码审查

状态：文档验收完成，提交记录以 Git 为准。

交付：现有仓库与 invLM 审查、C++ 主体架构、数学/接口契约、采样器调查和本计划。

验收：

- invLM 来源版本、实际接口、fallback 与核失败语义明确。
- 不假设 DispersionRootLab API，不引入 disba。
- 明确哪些是已观察的代码事实，哪些是待实现或待验证的设计。
- 用户不必安装独立反演/采样框架的分发目标明确。
- 下一步范围固定为 M1，没有把未测试的代码计入已完成成果。

本轮结果：已检查本地代码、基础环境和公开采样器资料；未运行物理或反演测试，
没有性能数据，也没有可交付求解器。未经验证的初期草稿已移出仓库。

建议提交：`docs: define M0 architecture and numerical acceptance plan`。

## M1 C++ 构建与多阶正演基线

状态：已完成，验收记录见 [M1 验证报告](m1-validation.md)。对应 Phase 1 的第一部分。

交付：固定版本依赖策略、最小 CMake 核心库与 CLI、模型验证、invLM 原样源码及
许可证/哈希清单、Dunkin 正演适配、逐行结果和错误诊断。
仅构建正演路径，不纳入 LM 或采样器。

验收：

- 干净 Linux 环境可构建；源码依赖准备完成后断网可重复构建，无本机绝对路径。
- CTest 验证模型边界、单位、模态编号、乱序/重复查询和错误输入。
- 均匀半空间与独立 Rayleigh 方程比对；普通分层至少一个独立参考验证。
- 保留 invLM golden 回归，但单独标注其只证明迁移一致性。
- 正常梯度层、低速夹层、高速夹层、强对比、频段边缘、截止或缺根均有具名案例。
- 缺根不减少输出行，不引入渐近备用值；无法证明完备性的案例记录为未解决。
- 记录首调用、重复调用与困难模型的时间和内存 baseline，明确测试机器与精度。

退出条件：发现误根/错阶时修复或明确限制支持范围；不能带着已知错误进入反演。
允许将尚无可靠参考的复杂场景列为未认证，但必须明确其不能用于科学结论。

建议提交：`feat: add validated invLM Rayleigh forward baseline`。

## M2 核函数与统一观测目标

状态：已完成，见 [M2 验证报告](m2-validation.md)。

交付：能量核、隐式物性导数、固定 Vs 参数化、Gaussian likelihood、log posterior 契约。
不实现 HMC。

验收：

- 根正确、导数正确、截止/分支稳定性三组测试独立运行。
- Vs/Vp/rho 分别对比能量核、隐式导数和多步长中心差分，报告误差随步长变化。
- 固定 Vp 和固定 Vp/Vs 的参数链式求导分别验证。
- 截止附近和根接近的困难案例有诊断，不能只检查良态模型。
- 有效正演值不会因核失败被抹去；梯度不可用时不返回伪零梯度。
- 非对角协方差与小型手算结果一致；非正定/错维协方差明确拒绝。
- 似然归一化项、先验测度和变换 Jacobian 的值与梯度单独验证。

建议提交：`feat: validate sensitivity and covariance-aware objectives`。

## M3 固定层数 LM 最小端到端版本

状态：已完成，见 [M3 验证报告](m3-validation.md)。Phase 1 最小可运行版本闭环。

交付：有边界、尺度归一化、阻尼与步长接受策略的 LM；合成生成和观测文件反演 CLI；
Python 模型/频散绘图；可复现输入和结果记录。M1–M3 合起来是 Phase 1 MVP。

验收：

- 线性最小二乘和已知非线性小问题验证求解器，而不只测试频散拟合。
- 无噪声、带噪声、相关噪声各有案例；数据、配置、种子、版本和终止原因完整保存。
- 多初值、边界触发、缺模态试算、初值无效、迭代上限等成功/失败路径可复现。
- 至少有基阶与基阶加第一高阶的配对反演，不把小残差解释为结构唯一。
- 一条文档命令可依次完成构建、CTest、合成反演、绘图。
- 运行报告含实际测试数、代价、模型误差、根/核异常数和运行开销。

建议提交：`feat: deliver fixed-layer LM synthetic workflow`。

## M4 固定层数反演完善与分辨诊断

按独立验收目标拆分：

- **M4a 已完成**：固定参数化的白化灵敏度谱、声明参数尺度、岭有效维度与模型分辨矩阵，
  以及模态/噪声/岭强度对照。见 [M4a 验收报告](m4a-validation.md)。未实现自适应分层。
- **M4b 已撤回**：按用户要求移除 AIC/BIC、独立验证评分、候选排名及相关实验。
  该路线不再作为自适应分层的开发前置条件；原代码和实验说明可从 Git 历史查阅。
- **M4c 暂缓**：按用户最新要求，暂停 LM 的自适应分层，包括自动拆层、合层和增减参数。
  不作为 LM 完善或 HMC 开发的前置条件；后续是否恢复另行决定。
- **M4d 已完成**：有界阻尼子问题、稳定下降量、收敛/停滞/失败分类及固定层数多初值回归。
  Release/UBSan 均 29/29；66 条对照轨迹保留 5 条停滞，见 [M4d 验收](m4d-validation.md)。

近期路线：固定层数 LM 完善 → 固定层数 HMC/NUTS → 独立跨维 RJMCMC。
层数由用户给定，LM 与标准 HMC 的一次运行中均不改变参数维度。
固定层数不要求固定层厚：目前沿用固定层顶、Vs 反演；若扩展到可变层厚，
先独立验收正厚度/有序界面参数化及其灵敏度，再接入两种算法。
不将尚未实现的层厚反演视为已支持功能，也不自动将其设为 HMC 的前置条件。

固定层数验收覆盖平滑梯度、清晰界面、低速层、浅部细节加深部平滑结构，
比较不同模态、噪声、频段和观测覆盖下的拟合、模型误差、触界和失败情况。
现有灵敏度与分辨诊断作为辅助分析，不用来自动决定层数。
每项只处理明确的数值问题，完成后独立提交。

## 每项完成时的提交规则

1. 只开发当前里程碑的必要实现。
2. 运行该项规定的测试，记录命令、环境和实际结果。
3. 同步示例、文档、限制与结果解释。
4. 检查差异和工作区，不提交生成结果、构建目录或未经验证的下一项草稿。
5. 为这一项创建独立 commit，并报告 hash、实现范围、验收结果和下一项。

用户已明确授权每项完成后 commit；不因此自动 push、发布版本或替用户选择远程服务。
