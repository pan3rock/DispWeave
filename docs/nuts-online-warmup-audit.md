# 原始初值的在线预热检查

本轮检验 [温和重启与矩阵检查](nuts-warmup-policies.md) 能否从原始初值运行，而非只在已到达的
检查点上表现良好。生产内核没有修改，使用 `1634504` 的二进制。

结论：四次运行均超时，未完成预热。全程启用温和策略出现效率退步，本轮验收未通过。

## 固定协议

两个原初值（参考 Vs −0.2 / +0.2），seed 20261023，45 个自由参数、125 个观测，
原物理先验与支持域不变；Gauss–Newton 初始质量矩阵、multinomial 树、dense 适应、
k=25、目标接受率 0.99、最大树深 10。各计划 300 预热＋100 正式状态，单链上限 120 秒。

比较两种方案，各两个初值：

1. 温和启动及重启，关闭矩阵检查。
2. 同样的温和策略，加在线最大刚性比检查，阈值 4。

本次矩阵检查在运行中实时计算 Jacobian、接受或拒绝候选，完整保留双平均和 RNG 状态，
不使用离线选好的矩阵。窗口在第 100、150、250 次预热结束时更新。
两条数值进程并行，四次任务合计墙钟预算约四分钟，不重试、不追加预算、不按结果调参。
先前 k=25、普通启动/重启结果来自历史保存记录，并非同批次配对计时。
主要比较评估次数与运行进度，不据墙钟差异宣称精确速度倍率。

```sh
python scripts/benchmark_nuts_warmup.py --exe build/dispweave \
  --reference results/crust-nuts-final --output results/nuts-online-policy-pilot-new \
  --metric-shrinkage 25 --policy-ablation
```

本地证据保存在 `results/nuts-online-policy-pilot/`，包括运行前固定的协议、输入/config 哈希、
脚本和二进制快照、完整已刷盘进度及矩阵决策。超时不读取未刷完的最终矩阵和样本文件。
转移评估下界不包含搜索、初始化、预检和被中断的转移；额外 Jacobian 另列，不能混为零。
只有完成运行才从成本文件核对全部调用；未进入正式阶段不报告冻结步长、ESS 或新后验验收。

## 已确定的启动问题

仅温和策略的原初值 0 / 1 在时限内分别完成 168 / 59 次预热，没有正式状态，
已完成转移分别消耗 12,684 / 12,781 次目标评估；观察到的发散与数值失败均为 0。
此前普通启动/重启＋k=25 的进度是 266 / 172 次。

为排除单纯的机器速度差异，在相同转移数处比较目标评估：

| 原初值 | 比较转移数 | 此前普通策略 | 温和策略 | 评估次数比 |
|---|---:|---:|---:|---:|
| 0 | 168 | 6,450 | 12,684 | 1.97 |
| 1 | 59 | 3,473 | 12,781 | 3.68 |

首次质量更新发生在第 100 次预热；仅前 25 次，两个初值的目标评估已由
897 / 2,067 增至 3,931 / 6,159。因此退化在矩阵更新前已经出现，不能归咎于在线矩阵检查。
原初值 1 的第 10 次转移步长约为 0.00655，此前为 0.04575；较小步长伴随更长的积分树。
原初值 0 的前 100 次评估从 2,454 增至 8,688，之后第 100–150 次也从 1,416 增至 2,894。

温和选项同时改变初始步长搜索、随机数消耗与双平均中心。上述对照能证明整个策略
在这些初值上退化，不能单独归因于某一个系数，也不能把不同轨迹上的转移数当成 ESS。
两条链均到达过树深 10；超时情况下只读实时进度，未从不完整 trace 推断确切树深截断次数。

## 在线矩阵检查结果

| 原初值 | 温和＋检查：预热次数 | 转移评估下界 | 已完成的额外 Jacobian | 决策 |
|---|---:|---:|---:|---|
| 0 | 169 | 12,747 | 2 | 第 100 / 150 次均接受，刚性比 2.3474 / 0.7021 |
| 1 | 59 | 12,781 | 0 | 未达到首次矩阵更新 |

两次也都在 120 秒超时，无正式状态，已完成转移未观察到发散或数值失败。
原初值 0 的前 168 次、原初值 1 的全部 59 次转移与不启用检查的方案逐字段一致，
包括位置、步长、评估次数及诊断。原初值 0 多完成一次是墙钟截断位置差异，不是算法路径提速。
本轮检查未拒绝任何矩阵，不能据此评价拒绝后的实际地壳效率；此前解析测试覆盖该分支。

[评估次数对比图（本地）](../results/nuts-online-policy-pilot/warmup-cost.png) 中，两条新策略的
共同路径重合。历史对照和本轮轨迹不同，图仅显示完成转移的计算代价，不表示独立后验样本数。


## 处理结论

局部检查点的成功不足以支持从原初值全程启用温和策略。本轮不切换默认配置，
不替换已有正式后验，也不将有限时间内未完成的运行标成完整在线预热验收。
下一项应将“首次启动”和“质量更新后的重启”分开：保留原启动行为，仅在质量更新后
尝试温和重启，并保持矩阵检查独立。需要先验证首次更新前随机路径逐位兼容，
再用相同预算评估后续窗口；不能直接假定这一调整必然解决问题。

本轮只扩展试验脚本和报告，没有修改生产采样器。验证包括 Python 语法检查、CLI 错误参数检查、
真实四次受限运行、输入/配置/二进制哈希、原始初值/先验/支持域一致性和矩阵检查之前的路径对照。
