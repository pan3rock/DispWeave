# 固定矩阵下候选步长目标的较长验证

继 [目标接受率短测](nuts-step-size-audit.md)，本轮延长两组候选的正式采样，验证短测中
降低目标接受率后的数值稳定性、混合及后验一致性。没有新增采样器启发式或修改生产内核。

## 事先固定的协议

- 候选：multinomial、目标接受率 0.90；原 slice、目标接受率 0.95。
- 各四条链，每条 100 次普通双平均步长适应＋1,000 个正式状态，随机种子从 20261024
  改为 20261025，chain ID 0–3。共八次任务、8,000 个计划正式状态。
- 与短测使用相同的四个已验收后验末状态、chain 0 最终质量矩阵和起始步长。
  45 维模型、125 个观测、数据协方差、物理 Vs 先验中心/尺度/边界及模态支持域不变。
  质量矩阵固定，所有新增适应选项及初始步长搜索关闭。
- 四个数值采样进程并行，每条最多 300 秒，总墙钟预算约 10 分钟。不补跑、不延时、不删除失败链。
- 对全部 45 个 Vs 与四个派生量检查：最大 R-hat≤1.01、最低 bulk/tail ESS≥400；
  正式期无发散、数值失败或树深截断，每条链必须实际移动。门槛写入运行前协议。
- 均值差/合并 MCSE、标准差比、分位数偏移用于与原 4×2000 后验作描述性一致性核查。
  复用起点且多参数相关，不将这些比较包装成独立显著性检验。

```sh
python scripts/benchmark_nuts_step_size.py --exe build/dispweave \
  --reference results/crust-nuts-final --output results/nuts-step-size-confirmation-new \
  --confirm-candidates
MPLCONFIGDIR=/tmp/dw-matplotlib python scripts/plot_nuts_step_size.py results/nuts-step-size-confirmation-new
```

本地证据在 `results/nuts-step-size-confirmation/`，包括冻结脚本/二进制、输入与配置哈希、
逐链轨迹和完整成本。独立审计要求与对应短测的配置相比只改变随机种子和正式状态数；
重新计算全部诊断，并核对正式状态与即时进度文件逐位相同。
默认六组短测模式仍保留，新增 `--confirm-candidates` 只选择上述固定确认协议。

## 结果

八条链全部完成，约 343 秒（5.7 分钟），无超时或补跑，共 8,000 个正式状态。
两组都通过预先声明的固定矩阵条件诊断：

| 设置 | 完整正式状态 | 最大 R-hat | 最低 bulk ESS | 最低 tail ESS | 条件诊断 |
|---|---:|---:|---:|---:|---|
| multinomial-90 | 4×1000 | 1.003380 | 1739.8 | 2521.3 | 通过 |
| slice-95 | 4×1000 | 1.003859 | 2149.4 | 2145.1 | 通过 |

| 设置 | 步长范围 | 正式评估/状态 | bulk ESS/千次正式评估 | bulk ESS/累计链秒（含适应） | 均值差最大合并 MCSE |
|---|---:|---:|---:|---:|---:|
| multinomial-90 | 0.3658–0.3693 | 15.948 | 27.27 | 2.605 | 1.79 |
| slice-95 | 0.2745–0.2985 | 14.905 | 36.05 | 3.415 | 2.66 |


现代 0.90 正式期支持域拒绝 0 次；slice 0.95 为 1 次。两组正式期的数值失败、发散和树深截断
均为零。预热阶段现代 0.90 有 2 次发散、0 次数值失败；slice 0.95 两项均为零，未删除这些记录。
正式目标评估数分别为 63,792 / 59,618；含初始化、预检和适应的总评估数为 70,082 / 65,956。
累计链时间为 667.78 / 629.45 秒，不应与四进程并行的约 343 秒总墙钟混淆。

相对原 4×2000 后验，49 个量的标准差比范围为：现代 0.90 的 0.9650–1.0345、
slice 0.95 的 0.9589–1.0385。2.5% / 50% / 97.5% 分位数的最大偏差分别为原后验标准差的
0.1313 / 0.1292 倍。这些描述性结果没有显示明显的后验位置或宽度变化。

## 半段检查与效率排序

| 设置 | 前半段最大 R-hat | 后半段最大 R-hat | 前 / 后半段最低 bulk ESS | 前 / 后半段 bulk ESS/千次正式评估 |
|---|---:|---:|---:|---:|
| multinomial 0.90 | 1.00625 | 1.00603 | 1126.6 / 684.5 | 35.29 / 21.48 |
| slice 0.95 | 1.00688 | 1.00862 | 1080.5 / 1083.3 | 36.23 / 36.36 |

两组前后各 500 状态也均达到 R-hat/ESS 门槛。按全部 49 个量中最低 bulk ESS/秒，
本轮 slice 0.95 比现代 0.90 高约 31%，而且半段效率估计更稳定。
这与前轮现代 0.90 的短测领先不同，不能沿用短测的赢家结论。

但两者没有统一的效率排序：现代 0.90 最慢的是事先列入检查的 `reference_quadratic`，
其 ESS 为 1739.8；仅看 45 个 Vs，现代内核最低 bulk ESS 为 2896.7，高于 slice 的 2149.4。
现代内核最低 tail ESS/千次正式评估为 39.52，slice 为 35.98。不能事后删除二次型来改变
预先约定的最差指标，也不能把 slice 的最差 bulk 优势说成它对所有参数和尾部都更好。

[参数与派生量的诊断图（本地）](../results/nuts-step-size-confirmation/step-size-confirmation.png)。
部分 bulk ESS 大于实际状态数是负自相关下允许的 ESS 估计，不代表生成了更多状态。

下一步优先把原 slice 的 0.95 作为从原初值验证的简单候选，保留现代 0.90 作为对照。
当前结果支持降低目标接受率值得进一步验证，不支持继续追求一个普遍最优的内核标签。


## 解释边界

这轮检验固定好矩阵、已有后验起点下的正式采样，不检验从原始分散初值开始的完整适应。
未重新长跑目标 0.99，因此前轮约 2.46 倍的效率比仍是短测估计，不能因本轮样本增加就升级为
长链速度对照。本轮两候选间同时改变内核和目标接受率，也不能把它们的差别只归因于某一个因素。

原四链正式结果及默认配置保持不变。通过这里的条件诊断不等同于证明全局探索完整，
也不自动替代原四链从头运行的验收。下一项若继续，应检验候选在原始初值与在线矩阵适应下的流程。
