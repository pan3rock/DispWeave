# 链 0 最后矩阵更新后的步长对照

接续 [原始四初值 0.95 验证](nuts-original-095.md)，只检查最后矩阵更新后的重启策略。
不改变后验、质量矩阵或 NUTS 内核，不从头重跑四条原始链。

## 预先固定的方案

- 起点：`nuts-original-095` 链 0 的零基转移 949 结束状态；此时即将执行第 950 次矩阵更新。
- 固定矩阵：用同链 450–949 共 500 个状态重建默认正则化协方差，再求逆得到动量协方差。
  与上一轮保存的重建矩阵核对一致；不使用超时运行中可能未完整写出的最终矩阵。
- 初始步长：原运行零基转移 950 实际使用的 0.150282685 左右，而不是更新前转移使用的步长。
- slice NUTS、目标接受率 0.95、标准双平均、最大树深 10；禁用矩阵适应、温和策略和刚性保护。
- 三组：无搜索＋50 次适应；合理步长搜索＋50 次适应；合理步长搜索＋150 次适应。
- 每组 4 个随机流，seed 20261026、chain ID 0–3；全部使用同一个起点，正式期各 200 状态。
- 每次最多 120 秒，四个数值进程并发，交错组别顺序。不重试、不延长、不挑选完成的随机流汇总。
- 主指标为 45 个 Vs 和 4 个派生量中的最低 bulk ESS / 总评估次数；成本包含搜索、预热、
  初始评估和预检。另报 tail ESS、半段诊断、接受统计、发散、树深与最大能量误差。

这里调用的是已经存在的 Stan 风格步长搜索：单步试探、步长倍增/减半、再启动标准双平均。
不是新增算法，也不声称与 Stan 随机路径逐步相同。四个随机流搜索会消耗随机数，故它们与
无搜索组的后续动量序列不完全配对。

```sh
python scripts/benchmark_nuts_terminal_step.py --exe build/dispweave \
  --source results/nuts-original-095 --output results/nuts-terminal-step-new
MPLCONFIGDIR=/tmp/dw-matplotlib python scripts/plot_nuts_terminal_step.py results/nuts-terminal-step-new
```

## 结果

| 方案 | 四次正式状态数（目标各 200） | 冻结步长范围 | 各次正式平均评估/状态范围 |
|---|---|---|---|
| 无搜索＋50 | 58 / 159 / 84 / 141 | 0.0412–0.0612 | 55.3–101.3 |
| 搜索＋50 | 200 / 172 / 172 / 154 | 0.0552–0.0773 | 51.2–58.7 |
| 搜索＋150 | 94 / 60 / 61 / 70 | 0.0579–0.0759 | 50.3–55.9 |

12 次中仅搜索＋50 的随机流 0 完整完成（119.5 秒）；其余均触及 120 秒上限。
所有已完成正式转移均无发散或数值失败，但这是部分轨迹的诊断，不等同于后验通过。
三组均有未完成重复，因此没有 pooled ESS/R-hat，也不能报告 ESS/总成本的赢家。
原预算不足以完成预定比较，诚实保留这一限制，没有追补采样。

在同样单次时限下，搜索＋50 的每个随机流都比无搜索组产出更多正式状态，但搜索会改变
随机数消耗，不是逐步相同随机轨迹的比较。搜索组每状态仍需约 50–59 次评估，接近原链 0
的 57.6 次，未恢复其他原始链约 15 次的成本。150 次适应未显示明确的正式成本优势，
且额外预热占用了更多时限；不能据此声称 50 次在所有场景最优。

搜索＋50 的正式平均接受统计范围约 0.927–0.964，搜索＋150 约 0.921–0.956。
单独强行放大步长不能保证仍达到目标接受统计。现有结果不支持把慢链完全归因于
“没搜索步长”或“末段只有 50 次”。下一项应在同一检查点比较更新前后矩阵，各自适应步长，
而不是继续添加双平均启发式。本轮不启动新的矩阵试验。

[步长及成本图（本地）](../results/nuts-terminal-step/terminal-step.png)。叉号表示不完整运行。

时间口径说明：冻结协议里 `max_sampling_wall_seconds=360` 是 12×120÷4 的名义并行预算，
不是实现的全局硬截止；实际协议到输出约 378 秒，包含调度与记录开销。
各子进程均按 120 秒独立截止。仓库脚本已将该元数据字段改为
`nominal_worker_sampling_budget_seconds`，保存的原协议及运行脚本不改写。


## 解释及检查边界

同一检查点的随机重复不能检验从分散起点的全局收敛；短链 ESS 只用于条件性效率比较。
某组任何一次未完成，都不计算该组 pooled ESS，也不将其他组的完成视为完整后验验收。
这里不是原运行的位级续跑：重建物理起点有浮点往返误差，随机流重新初始化。

生产内核没有修改；没有启用新默认配置或覆盖原正式结果及本地网页。
新脚本做语法检查、真实数值运行及独立输入/输出审计，不重复未受影响的 C++ 回归。
原始数据、配置、脚本、生产二进制及依赖哈希保存在本地 `results/nuts-terminal-step/`。
本轮仅用已有最大能量误差诊断；没有新增逐状态总能量输出，因此没有计算 E-BFMI。

后续 [矩阵隔离对照](nuts-metric-pair.md) 八次全部完成，发现新矩阵虽然状态生成更慢，
主体有效样本效率反而改善，修正了只从步长及调用数判断退化的倾向。
