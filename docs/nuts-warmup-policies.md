# NUTS 预热重启与局部矩阵检查（实验选项）

继 [第 150 次质量更新核查](nuts-window150-audit.md)，增加两个独立、默认关闭的选项。
目标是减少步长重启过冲，以及避免局部最大刚性骤增的质量更新。目标密度、物理先验、
支持域和正式期 NUTS 转移规则不变。这是本项目的实验策略，不是声称复刻 Stan 的默认预热。

后续 [原始初值在线检查](nuts-online-warmup-audit.md) 发现温和策略会拖慢初次启动。
下文的检查点短测结果仍成立，但不足以支持全程启用；默认继续关闭。

## 实现

`conservative_warmup = true` 要求存在自适应预热。它同时作用于首次预热和接受质量更新后的重启：

- 若启用 `find_initial_step_size`，用四组固定随机动量反复检查单步积分，只减半、不放大步长；
  四组的单步接受统计均须至少 0.8，最多 12 轮、48 次目标/梯度调用，失败明确报错。
- 双平均的中心由起始步长的 10 倍改为 1 倍。质量更新后，从上一段双平均的平滑步长开始搜索。
- 双平均本身仍可以增大步长；该选项不是整个预热的步长上限。正式期冻结步长和质量矩阵。

`metric_max_stiffness_ratio = 4.0` 开启独立矩阵检查，0 关闭，开启值必须有限且至少为 1。
每个适应窗口结束时，在同一个当前位置计算局部正定曲率代理 G，比较候选和旧矩阵的
`lambda_max(M^-1 G)`。超过比值上限时拒绝更新，保留旧 M、协方差先验和持续中的双平均状态，
不重新搜索步长；该窗口的数据随后清空，正常进入下一窗口。接受更新才执行重启。
4 允许局部最大频率增长到 2 倍，是根据既有诊断选定的实验阈值，不代表最优值。
该检查不控制完整条件数，也不保证全局几何或混合质量。

C++ 接口允许提供正定 `local_curvature` 回调；CLI 目前要求 `reference_gaussian_vs`，使用
白化数据 Jacobian 与物理 Vs 先验构造的 Gauss–Newton 矩阵，和现有初始预条件器一致。
它不是精确后验 Hessian。一次候选更新额外计算一次 Jacobian，失败明确终止；不将其伪装成支持域拒绝。
`chain_N_metric_decisions.txt` 即时刷盘保存接受/拒绝及刚性比；`chain_N_cost.txt` 的
`guard_evaluations` 单独记录这部分调用。总评估工作量应计算
`target_evaluations + preflight_evaluations + metric_evaluations + guard_evaluations`。

示例（在原有 `[nuts]` 配置内）：

```toml
kernel = "multinomial"
find_initial_step_size = true
metric_adaptation = "dense"
metric_shrinkage = 25.0
conservative_warmup = true
metric_max_stiffness_ratio = 4.0
```

## 有限检查点试验

脚本：`scripts/benchmark_nuts_restart.py`；本地证据：`results/nuts-restart-pilot/`。
使用此前保存的两个 45 维检查点，每种方案两个固定种子 17/2026，各 20 预热＋10 正式状态，
最大树深 8，两个数值工作进程，单次 30 秒上限。配置、二进制、脚本和输入哈希在运行前保存。
比较普通重启、温和重启、温和重启＋矩阵筛选。没有超时重试或追加预算。

本试验重置 RNG 和双平均，因此不是原链的逐位续跑。三种方案均从重建的上一窗口平滑步长
开始（chain 0 为 0.1707675，chain 1 为 0.1278182）。矩阵检查在这里依据已保存的 G 离线选择，
之后固定质量矩阵：chain 0 接受候选（刚性比 0.7027），chain 1 保留旧矩阵（刚性比 11.8549）。
完整在线回调、接受/拒绝流程和额外调用计数另外由 C++ 与 CLI 测试覆盖。
chain 0 的后两种方案参数相同，重复结果不算独立证据。

运行期间有构建和回归测试并发，因此主要比较目标评估次数，不把本轮墙钟差异当精确速度倍率。
超时只汇总已刷盘完成的转移，遗漏正在执行的转移与未写出的搜索成本，是下界。
到达树深 8 与真正因上限停止不同；脚本的 `depth8` 只表示到达该深度。

结果如下；每格顺序均为种子 17 / 2026，“评估”只统计已完成转移，不含搜索。

| 检查点 | 方案 | 完成预热＋正式 | 转移评估 | 预热发散 / 数值失败（两次合计） |
|---|---|---|---|---|
| chain 0 | 普通 | 20＋0 / 19＋0（均超时） | 3091 / 3091（下界） | 4 / 0 |
| chain 0 | 温和 | 20＋10 / 20＋10 | 1202 / 1250 | 0 / 0 |
| chain 0 | 温和＋矩阵筛选 | 20＋10 / 20＋10 | 1202 / 1250 | 0 / 0 |
| chain 1 | 普通 | 16＋0 / 14＋0（均超时） | 3062 / 3074（下界） | 3 / 3 |
| chain 1 | 温和 | 15＋0 / 20＋7（均超时） | 3057 / 3109（下界） | 0 / 0 |
| chain 1 | 温和＋矩阵筛选 | 20＋10 / 20＋10 | 1762 / 1346 | 0 / 0 |

组合方案的四次运行全部完成，无发散、数值失败或树深截断；包含初始化、预检和搜索的
总目标调用分别为 1208、1256、1768、1352。这里只使用保存的 G，未产生在线 guard 调用；
完整在线方案每次窗口判断还要加一次 Jacobian。chain 0 的正式步长为 0.17261 / 0.15659，
chain 1 为 0.09775 / 0.11056。四次用时约 11–16.5 秒；普通方案四次均达到 30 秒上限。

这支持此前的两个局部诊断：chain 0 主要是重启过冲，chain 1 还需要防止矩阵刚性恶化。
只改重启不足以解决后者。本次没有运行原始初值的完整在线自适应流程，因此不宣称整个
300/1000 次预热问题已解决，也不能把四次局部成功当成全局稳定性的保证。

这些短程正式状态仅用于检查冻结后的行为，不能估计可靠 ESS/R-hat，不能代替完整后验验收。
原 `results/crust-nuts-final/` 与本地结果网页继续保留。新选项均不切换为默认。

## 验证

- 相关高斯目标上，三种策略分别使用三个种子验证白化均值、方差和交叉矩，以及正式期冻结和重放。
- 所有矩阵候选拒绝时，验证样本、步长、最终质量矩阵与不适应质量的对照逐位相同，且不额外搜索。
- 检查搜索预算、局部刚性的质量约定、非法阈值、无效曲率和有限次搜索失败。
- 真实三层频散 CLI 检查物理先验中心不变、每窗口一次 Jacobian、决策日志、搜索和成本计数。
- 关闭新选项，对照保存的旧二进制：slice、multinomial＋搜索、multinomial＋搜索＋k=25
  各三条链，100 预热＋80 正式状态，共 63 个采样、轨迹、质量、更新、搜索和成本文件逐字节一致。

Release CTest 首次 76/77，新增 CLI 测试读入含状态字符串的搜索日志时类型设置有误；
改为字符串读取后该项通过，最终 77 项全部通过。UBSan 的五项 NUTS 检查全部通过。
