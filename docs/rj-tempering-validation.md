# 固定 K=4 的并行温度交换验证

已实现可选 parallel tempering（PT），并完成一次预先限定预算的对照。
**改善明显，但冷链尚未通过混合验收。** 不把这一结果当作可靠的层数概率或已收敛后验。

## 实现与不变的统计目标

实现依据见[固定提交的开源审查](rj-open-source-review.md)，采用 BayesBay/Eryn 使用的
likelihood-only tempering 思路，未复制其源码。温度 T 的目标为
`prior(x) * likelihood(x)^(1/T)`；物理参数先验、支持域和 RJ Hastings 因子不加温。
原 birth/death/interface/velocity 各 1/4，不可用动作仍是自转移。

相邻温度交换的 log 接受比为 `(1/Ti - 1/Tj) * (logLj - logLi)`。
模型、原始 log likelihood 和 log prior 一起交换，复用缓存，不增加正演调用。
随机数流留在固定温度槽位；交换使用单独的随机数流。每 10 步交替尝试不重叠邻接对。
温度、局部步长、交换间隔在预热和正式阶段均固定，无自适应。

可选 CLI 配置（不加此表仍走原单链路径）：

```toml
[rjmcmc.tempering]
temperatures = [1.0, 2.0, 4.0, 8.0]
swap_every = 10
```

每个 `rj_starts` 对应一组独立温度梯，其起点在该梯的所有温度上复制。
`chain_i_models.txt` 只记录交换后的 T=1 状态，兼容 `rj-predict`。
`ladder_i/temperature_j_models.txt` 保存各固定温度的正式状态；
`*_local_trace.txt` 显式区分局部更新后的 K 与交换后的 K。
`swaps.txt` 保存交换前 logL、身份和接受决定，`replicas.txt` 保存每步交换后身份。
普通 `rj_diagnostics.py` 的单链 trace 格式不能用于 PT，应使用本轮专用分析。
这里的“并行温度”指算法；当前各温度的正演按顺序执行，没有新增线程。

## 预先声明的预算与结果

同原 K=4 的数据、条件先验、四起点和提议尺度；四组独立温度梯，各温度
2500 预热＋25000 正式，共 **440000 次局部提议**，等于原四链各 10000＋100000 的预算。
冷链正式样本合计 100000，热链不拼入后验诊断。所有温度的预热、初始化及起点检查均计入成本。
协议在采样前保存至 `results/rj-pt-k4/protocol.json`；只运行一次，没有延长、重试采样或扫描温度。

| 指标 | 原 K=4 | PT 冷链 |
|---|---:|---:|
| 最大 R-hat | 1.70622 | 1.05136 |
| 最低 bulk ESS | 6.31 | 116.65 |
| 最低 tail ESS | 13.40 | 43.93 |
| 所有温度总目标评估 | 203560 | 205448 |
| 最低 bulk ESS / 1000 次评估 | 0.0310 | 0.5678 |

诊断覆盖三个有序界面、四个 Vs 和同一 31 点深度网格。
门槛仍为所有 R-hat≤1.01、bulk/tail ESS≥400，因此**未通过**。
最低 bulk ESS 按总评估成本归一化后约提高 18.3 倍，但未收敛时 ESS 本身也是诊断估计，
不能据此宣称可靠样本吞吐提高 18 倍，更不能外推跨维采样效率。

正式相邻交换率为 52.6%–59.7%；每个副本在正式期完成 46–66 次冷→热→冷往返。
频繁交换没有保证冷链收敛。全部温度预热和正式期均无正演失败或数值失败。
采样及输出约 22.47 秒；原实验运行环境有并发任务，不作墙钟加速比比较。

## 验证与复现

- Release 全部 CTest 78/78 通过；补充 PT CLI 重现及冷链预测测试后定向检查通过。
- 原冻结二进制与新二进制，在相同 K=4 四起点、20＋100 步下，模型、轨迹和失败记录逐字节相同。
- 内核测试覆盖 T=1 极限、非均匀 K 先验下各温度的解析分布、交换平衡、缓存、调用次数、
  随机流重现、非法温度，以及热链仍拒绝无效正演；另核对连续双峰目标在每个温度的积分概率。解析测试为有限 Monte Carlo 检查。
- UBSan 的 PT 内核与 CLI 测试通过，无未定义行为报告。
- 全部 400000 个各温度正式模型与 440000 次局部转换核对；交换表、身份、成本和支持域一致。
- 独立读取结果，逆转交换后检查拒绝状态与接受比，重新计算全部参数/深度诊断；
  对四组×四温度×三个时点共 48 个状态重新正演并计算归一化似然，最大误差 8.6e-11。
  这是缓存/数据契约核查，不是全域根完整性证明。只读审计最初使用了错误的状态文本标签，
  改为实际 `valid` 标签后通过，没有重跑采样。

后续若继续，应先利用现有冷链定位剩余慢变量/结构分支，再决定是否需要一次针对性的联合提议；
不立即增加温度、延长链或把 PT 推广到全跨维生产结果。
